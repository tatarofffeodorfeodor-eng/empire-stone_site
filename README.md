# Империя камня — сайт

Сайт компании «Империя камня»: каталог, калькулятор, корзина, личный кабинет,
админ-панель. Ванильный JS (ES-модули), без фреймворка, собирается через Vite.
Бэкенд — Supabase (Postgres + Auth + Storage), вызывается напрямую из браузера
(защищено правилами доступа в базе, см. `supabase/schema.sql`) плюс две
маленькие serverless-функции Netlify для того, что не должно уходить на клиент.

## Структура

- `index.html` — разметка страницы и точка входа Vite
- `style.css`, `site.css` — стили
- `public/img/` — фотографии (логотип, заводские фото работ для первого запуска) — копируются в сборку как есть
- `supabase/schema.sql` — вся схема БД: таблицы, права доступа (RLS), затравочные данные, хранилище для фото
- `netlify/functions/`
  - `send-lead.js` — пересылает заявки/заказы в Telegram
  - `orders-by-phone.js` — отдаёт личному кабинету только его заказы (требует `SUPABASE_SERVICE_ROLE_KEY`, см. ниже)
- `src/`
  - `main.js` — точка входа: подтягивает каталог из Supabase, затем запускает роутер
  - `router.js` — переключение вкладок, рендер текущего экрана, общие обработчики кликов
  - `admin.js` — админ-панель (вход через Supabase Auth, правки каталога/цен/галереи/заказов/заявок — пишутся сразу в БД)
  - `contact-widget.js` — плавающая кнопка «Связаться» и форма обратного звонка
  - `lib/`
    - `supabase.js` — клиент Supabase для браузера (`anon`-ключ, безопасен для клиентского кода — все права разграничены в БД)
    - `leads-orders.js` — создание заявок/заказов + их чтение для админки
    - `cabinet-api.js` — запрос истории заказов личного кабинета через серверную функцию
  - `data/` — заводские каталог/материалы/галерея (используются как стартовые данные и запасной вариант, если Supabase недоступен) + `remote.js` — загрузка из БД и CRUD для админки
  - `state/` — локальное состояние на устройстве (корзина, избранное, кэш «мои заказы») поверх `localStorage`
  - `calculator/` — логика расчёта стоимости (объём, плитка, подоконник, круглый стол)
  - `views/` — HTML-разметка и обработчики событий для каждого экрана (каталог, работы, о нас, калькулятор, корзина, кабинет, вход)
  - `ui/` — мелкие переиспользуемые вещи: `$`/`$$`, тосты, конфетти, анимации, лайтбокс

## Бэкенд: что где хранится и кто что может

| Данные | Источник | Кто читает | Кто меняет |
|---|---|---|---|
| Каталог, цены на камень, фото работ | Supabase (`products`, `materials`, `gallery`) | Все посетители | Только админ (через `/#admin`) |
| Заявки на обратный звонок | Supabase (`leads`) | Только админ | Любой посетитель может создать (форма) |
| Заказы из корзины | Supabase (`orders`) | Админ — все; покупатель — только свои (по телефону, через серверную функцию) | Создаёт любой вошедший покупатель; статус меняет только админ |
| Корзина, избранное, демо-вход, сохранённые расчёты | `localStorage` браузера | Только это устройство | — |

Вход покупателя в кабинет остаётся демо-режимом (ввод телефона без SMS-кода) —
это был осознанный выбор при проектировании (SMS-подтверждение не входит в
бесплатный тариф Supabase). Из-за этого прямой публичный доступ к чужим
заказам по номеру телефона закрыт на уровне базы; кабинет получает свою
историю заказов через функцию `orders-by-phone`, которая сама фильтрует по
телефону на сервере.

## Настройка бэкенда (один раз)

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатного тарифа достаточно).
2. Откройте **SQL Editor** в панели проекта → вставьте содержимое `supabase/schema.sql` целиком → **Run**.
3. **Authentication → Users → Add user** — создайте свою учётную запись админа (email + пароль, которым будете входить в `/#admin` на сайте).
4. В **SQL Editor** выполните (подставив свой email):
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'ваш-email@example.com';
   ```
5. **Project Settings → API** — скопируйте `Project URL`, `anon public` ключ и `service_role` ключ.
6. Локально: скопируйте `.env.example` в `.env`, впишите `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
7. На Netlify: **Site configuration → Environment variables** — добавьте все четыре переменные:
   `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_URL` (то же значение, что и VITE_SUPABASE_URL), `SUPABASE_SERVICE_ROLE_KEY` (`service_role` ключ — секретный, только для сервера).
8. Задеплойте (или дождитесь автодеплоя после пуша) — после этого каталог/цены/фото будут общими для всех посетителей, а `/#admin` попросит email и пароль вместо PIN-кода.

Если .env не настроен (ни локально, ни на Netlify) — сайт продолжает работать
на заводских данных из `src/data/*.js`, просто без общей базы: админ-панель
покажет сообщение, что бэкенд не настроен, а не сломается.

## Разработка

```bash
npm install
npm run dev     # локальный сервер с горячей перезагрузкой
npm run build   # собрать в dist/
npm run preview # посмотреть собранную версию
```

## Деплой

Сайт подключён к Netlify. `netlify.toml` задаёт команду сборки (`npm run build`)
и папку публикации (`dist`), а также папку serverless-функций
(`netlify/functions`). При пуше в ветку `main` сайт обновляется автоматически.

Если после этого коммита Netlify не подхватит новые настройки сборки сам —
в Netlify UI (Site settings → Build & deploy) нужно проверить, что Build
command = `npm run build`, Publish directory = `dist` (обычно `netlify.toml`
перекрывает старые настройки UI автоматически).
